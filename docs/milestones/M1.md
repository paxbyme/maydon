# M1 — accepted foundation

## Delivered

- M0 product requirements, architecture, permission matrix, ERD, operational gates and traceability.
- NestJS API and separate worker foundation; public versioned health/version routes and generated OpenAPI.
- Player, owner and admin Flutter shells with shared theme, Dio transport, Riverpod, GoRouter and uz/ru/en localization.
- Player Android/iOS runners and all npm/Flutter lockfiles.
- Docker API/worker/PostgreSQL/Redis configuration, setup/verification scripts and cross-platform CI.
- Exact NestJS dependency updates plus scoped Multer/js-yaml security overrides; see security.md.

No booking, games, identity or business database APIs are implemented yet. The worker has no outbox handler. Production startup is deliberately disabled. Health is process liveness, not database readiness.

Bootstrap npm dependency resolution used the host Node 20 with engine strictness disabled for installation only; application acceptance used pinned Node 22.23.1 in Docker and CI.

## Security changes

NestJS common/core/platform-express: 11.2.8; Swagger: 11.4.7. Scoped overrides select Multer 2.5.0 and js-yaml 5.5.0 for their respective Nest parent packages. CI enforces npm audit at moderate severity. No blanket `npm audit fix --force` or major Nest upgrade was used. Node dependencies were reinstalled cleanly because npm initially retained stale overridden versions; the resulting audit reported zero findings.
