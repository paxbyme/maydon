# M2 — database, audit and outbox foundation

M1 was accepted on CI run 41240746027 before starting this milestone.

## Changes

- Prisma 6.19.3 core model: users/roles, owner memberships, facility/sport translations, resources/staff assignments, bookings/blocks/occupancy/history, games/members/invitations, audit, idempotency, outbox and inbox.
- Three reviewed migrations add PostgreSQL exclusion/check constraints, composite resource/source foreign keys, deferred mandatory ledger consistency, immutable price/policy snapshots and append-only audit records.
- Database and audit modules; consistent HTTP errors with generated request IDs and no echoed private input.
- Separate worker now polls durable outbox events with concurrent lease claiming, expiry recovery, fenced acknowledgements, backoff and dead-letter states. Inbox insertion and delivery acknowledgement are atomic. External adapters explicitly remain unavailable.
- Isolated real-PostgreSQL integration configuration, migration-before-start Compose dependency and CI database job. Runtime images remain non-root; build/test images retain tooling separately from pruned runtime dependencies.
- Scoped Prisma CLI dependency security patch; npm install audit reports zero findings. See security.md for the compatibility tradeoff.

## Data/API summary

Core tables and SQL constraints are new. No business HTTP routes are exposed yet. Health/version remain public under /api/v1. Errors now use `{code, message, requestId}` and `X-Request-Id`. Production startup remains disabled. No live customer data or external message delivery is involved.

## Verification

- Prisma formatting, client generation, TypeScript compilation and three HTTP/contract/configuration tests passed.
- Initial fresh migration succeeded; the first integration run revealed a pruned test-image dependency issue. Separating build/test and runtime stages fixed it.
- A clean PostgreSQL run passed 13 integrity/recovery tests: fifty-customer race (one success), booking/block race, buffered adjacency, required/same-resource ledger entries, atomic cancellation, immutable snapshots/audits, transactional rollback, concurrent claims, expired lease fencing, retry/dead-letter behavior and idempotency/email uniqueness.
- The final clean PostgreSQL run passed all 14 integration tests, including actual worker-process delivery and graceful shutdown. Full Compose startup applied all three migrations before API/worker startup.
- Type-check and Prisma format checks passed; npm audit remains clear. Final CI acceptance pending. M3 has not started.

## Limits

This is database and worker infrastructure, not the booking or game feature. Application authorization, booking windows/prices/calendar logic, resource-row locking in business services, identity/session challenges and full booking/game journeys remain assigned to later milestones. Exact retention periods and external delivery providers remain launch decisions. Direct infrastructure administrators can alter database objects; append-only enforcement is for normal application writes, not a replacement for controlled infrastructure access.
