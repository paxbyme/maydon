# M5 — owner onboarding, facilities and discovery

State: in progress. Owner application and manual review flow implemented; M5 is not accepted.

## Available flow

Verified owners submit a registered business name and private ownership evidence notes from the owner Overview or Facilities tab. Applications appear as pending, approved or requiring changes. Rejected applications can be corrected and resubmitted. One pending application per applicant is enforced under a user-row lock.

MFA-verified platform administrators use Applications to read private evidence and approve or reject with a reason. Administrators cannot review businesses they belong to. Decisions lock the application row, require pending status, and atomically commit audit records and an in-app notification outbox event. Evidence access is audited. Previous decision reasons are retained as encrypted audit envelopes when a rejected application is resubmitted.

Evidence notes are encrypted with a purpose-separated AES-GCM key. List responses exclude evidence; private endpoints return `Cache-Control: no-store`. Evidence notes are an initial review input, not a substitute for the document-upload workflow still required below. No automatic owner approval or facility publication is implemented.

## Data and contract

Migration `202611020001_owner_evidence` adds nullable `OwnerProfile.evidenceCiphertext` without changing existing records. Existing applications without evidence cannot be approved through the new API.

- `GET /api/v1/businesses`: own applications, cursor pagination, 25 per page.
- `POST /api/v1/businesses`: verified applicant submits a pending application.
- `PUT /api/v1/businesses/:id/submission`: owning verified member resubmits a draft/rejected application.
- `GET /api/v1/admin/businesses`: MFA-verified administrator's pending queue.
- `GET /api/v1/admin/businesses/:id/evidence`: audited private evidence read.
- `PUT /api/v1/admin/businesses/:id/review`: audited approval/rejection with reason.

The generated Dart client now supports typed arrays and scalar query parameters, including nullable pagination cursors. Owner/admin screens use generated operations and existing authorized session handling. All new labels and errors are localized in Uzbek Latin, Russian and English.
